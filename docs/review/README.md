## 审查方法

### 三阶段执行

1. **阶段 1 概览**：统计规模、读取入口与配置、判定风险等级为高（Red），据此走完整 SPEAR 流程。
2. **阶段 2 逐行**：对全部 134 个源文件逐个通读，按 SPEAR 五维记录候选发现。前端页面与组件层由子代理完成全量覆盖。
3. **阶段 2.5 证据验证**：对每条候选发现执行 5 步取证（文件存在 → 代码如述 → 防护是否已在别处 → 是否有意设计 → 修复是否引入回归），剔除误报并标注置信度。

### 本次使用的验证手段

除静态阅读外，为若干关键发现构造了运行时探针（探针脚本已删除，不留在仓库）：

| 手段 | 目的 | 结论 |
|------|------|------|
| 启动服务 + 造密钥 + 发请求 | 确认 `/v1/models` 子路由的鉴权边界 | 平台访问密钥可调用 `POST /v1/models/refresh` 与 `DELETE /v1/models/status`（均返回 200） |
| 启动服务（未设 `ADMIN_KEY`）+ 跨源简单请求 | 确认首登 setup 端点的可达性 | 跨源页面用 `text/plain` 简单请求成功创建 login key（201），合法用户随后被 403 拒绝 |
| 调用 `config.reload()` 前后对比 | 确认热重载是否保持 `resolveModelOptions` 的返回形态 | 重载后 `auto`、`config_name` 覆盖、未登记模型的返回对象丢失 `scene` / `reasoning` 字段 |
| 执行 CIM 过滤器命令 | 确认 `isClientRunning()` 的服务会话分支 | 引号拼接错误导致 `Get-CimInstance` 抛错；正确写法返回进程数 7 |
| `node src/test/unit.test.js` | 测试有效性 | 135 个用例通过 |
| `node src/test/growth.test.js` | 测试有效性 | 11 个用例通过 |
| `npx tsc -b --force`（`web/`） | 前端类型检查 | 通过，退出码 0 |
| `git status --short` 前后对比 | 测试是否污染真实状态 | 无变更 |

## 术语与约定

- 行号引用格式为 `相对路径:行号` 或 `相对路径:起始行-结束行`，均为实际读取过的区间。
- 严重级别：`[CRITICAL]` 安全漏洞 / 数据丢失 / 生产崩溃；`[MAJOR]` Bug / 逻辑错误 / 重大性能退化；`[MINOR]` 降低维护成本的改进；`[NIT]` 风格与命名。
- 置信度：`确定`（已读代码且排除「防护已在别处」）/ `高`（已读代码，未验证运行时）/ `中`（静态推断，未验证调用链）。`中` 及以下不标记为 CRITICAL/MAJOR。
- 「实测」表示本次构造探针实际运行过，结论附命令输出摘要。
