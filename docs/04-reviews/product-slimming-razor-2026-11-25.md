# Hai Razor：RelayGate 产品功能梳理与瘦身专项审查

> 审计日期：2026-11-25 · 基线：当前工作树（v3.1.0，`package.json`）· 视角：产品经理 + 剃刀裁决
> 历史审查（`product-audit-2026-10-10`、`frontend-existence-audit-2026-10-15`、`code-audit-2026-11-25`）只作为线索，**所有裁决以当前代码事实为准**。

## Verdict

- **裁决**：保留核心 / 合并若干 / 延后一批 / 删除一批 / 替换若干 / 先证明若干
- **一句话理由**：RelayGate 是一个单人自托管的多平台 AI 账号网关，核心价值闭环是「接入账号 → 稳定转发 → 看额度与成本 → 排障」。当前功能表里真正违反这条闭环的不是核心能力，而是**成长中心的写操作面、若干只为完整性存在的配置/字段/端点、以及成长面板里仍残留的游戏化文案**；删除这些不会破坏核心价值，反而能消除定位漂移。
- **剃刀原则**：每个功能必须挣得独立存在——删除它会破坏真实用户目标、抹掉真实区分、隐藏真实风险、或把不可避免的复杂度推给更差的归属。只因习惯、对称性、想象中的未来或"网关应该都有"而存在的，一律砍、合并、延后或要求举证。
- **未审范围（防误砍）**：`node_modules/`、`web/dist/`、`logs/`、`output/`、`backups/`、`design/`、`.history/` 等运行/构建产物；`docs/` 与 `scripts/` 仅作证据，不裁其存在性；视觉风格、移动端断点、安全漏洞整改属其他审查线（见 `docs/04-reviews/code-audit-2026-11-25/`），本轮只裁**功能存在性**。

### 1.2 产品真实定位（由代码而非 README 得出）

- 唯一用户：机器主人本人；默认 `127.0.0.1:19900` 本机进程（`README.md:7-9`）。
- 真实价值排序（按产品审计）：① 还有多少额度 → ② 账号有没有死 → ③ 转发有没有出错 → ④ 接入新账号 → ⑤ 偶尔改签到时间。
- 因此"可见功能"的判定基准是：**它是否服务于上述五件事之一，或是否属于支撑这五件事的隐性必需层**。

### 1.3 访问行为的证据边界

**本项目没有埋点/用户访问日志**（历史审查亦确认）。本次以 `logs/*/traffic.jsonl` 的文件存在性、代码中的入口层级（侧栏/折叠/二级 tab）、以及单人自托管场景的合理行为作为**推断证据**，并明确标注置信度。凡涉及"打开频率低于 5%"的判定，均属于**产品判断/待证明**，不把它伪装成真实统计数据。

## 3. 三维功能分类（用户价值 / 业务目标 / 使用频率 / 存在形态）

### 3.1 强需求功能（核心闭环必需）

| 功能 | 用户价值 | 业务目标 | 使用频率（推断） | 存在形态 | 判定 |
|---|---|---|---|---|---|
| 三协议转发（OpenAI/Anthropic/Codex）+ SSE 流式、工具调用、截断续写 | 让 IDE/脚本直接用免费账号额度 | 产品的存在理由 | 极高（日均大量，traffic 日志证实） | 显性核心 | 强需求 / 高频 / 隐性必需底座 |

### 3.3 隐性必需功能（用户不主动打开，但缺了核心流程就坏）

| 功能 | 不主动打开的原因 | 缺失后的具体故障 | 判定 |
|---|---|---|---|
| 鉴权/模型 ACL/按 key 限流 | 用户不关心 | 越权、烧额度、安全边界失效 | 隐性必需 / Keep |
| 选号 FEFO/冷却/指数退避 | 后台算法 | 账号被撞死、成本失控 | 隐性必需 / Keep |
| SSE 流中途失败处理（stream-gate） | 用户不知道它存在 | 错误文本被当模型输出 | 隐性必需 / Keep |
| 请求上下文 `AsyncLocalStorage` + traffic 记账 | 后台 | 排障时请求无法串联、成本失真 | 隐性必需 / Keep |
| 调度器跨进程锁、优雅停机 | 后台 | 重复备份/轮换、SSE 硬切 | 隐性必需 / Keep |
| 启动期健康检查与密钥失配熔断 | 后台 | 坏配置静默运行、凭据解不开 | 隐性必需 / Keep |
| 精确/估算/无计量三拆、积分与 token 双口径、`unlimited` 语义 | 数据规则 | 成本误判、显示错误 | 隐性必需 / Keep（绝对不可剃） |

## 5. 必须保留的复杂性（绝对不要碰）

| 复杂性 | 为什么必要 | 越过哪里开始伤害 |
|---|---|---|
| 积分口径 vs ZCode token 口径分离 | 把 1e8 token 当积分求和会让成本全错 | 不要统一单位，不要做"相加"便利函数 |
| `unlimited` 独立于 `remaining` | "不限量 ≠ 0"；显示成 0 会被误读为无额度 | 不要把它折叠成一个数字 |
| `isLoginKeyRejection` 区分两类 401 | 管理密钥失效与转发密钥失效语义不同 | 不要合并成 `if (status===401)` |
| 请求取消（AbortSignal 贯穿） | 路由切换后旧响应不能覆盖新数据 | 不要为简化删 signal 透传 |
| 定时任务跨进程锁与幂等 | 防重复备份/轮换，数据损坏 | 不要"简化"成无锁调度 |
| `stream-gate` 与错误帧 | 防止错误被当模型输出 | 不要用统一 try/catch 抹平 |
| 精确/估算/无计量三拆、Trae 滞后判断 | 成本信任的根基 | 不要让 UI 隐藏口径来源 |
| 登录密钥一次性明文展示与 `safetyBackup` | 泄露面与不可撤销操作的护栏 | 不要为了方便改成持久明文或免确认 |
| 健康检查真实化、密钥失配熔断 | 静默坏配置的最后防线 | 不要回退到硬编码 `status:'ok'` |

## 7. 风险评估与护栏

### 7.1 行为保持闸门

| 改动 | 必须保持的可观察行为 | 验证命令 |
|---|---|---|
| D1 删成长写按钮 | 后台每 4h 自动成长任务仍执行，通知仍发出；`npm run test:growth` 全绿 | `npm run test:growth && npm run build:web` |
| D2 删 `TOOL_PROTOCOL` | 工具调用形态仍由上游响应归一化，三种协议出口行为不变 | `npm test` + `npm run lint` |
| D3/D4 删零引用导出/字段 | 页面渲染与 API 响应不变；TS 编译零错误 | `npx tsc -b --force && npm run lint` |
| H1 隐藏成长面板 | 后台 job 不受影响；恢复路径明确（git revert 或加回入口） | 检查 `scheduler.js` 的 `scheduleGrowthPoll` 未被改 |
| H2 合并客户端接入 | 首次接入说明仍在一屏内可达；不出现"密钥创建后不知道放哪"的断裂 | 手工点一遍首登流程 |

### 7.2 可能的反弹与护栏

- **最可能的反弹**：成长中心被删后，未来有人以"上游有这个能力"为由把读/写端点重新接回 UI。→ 护栏：在 `known-limitations.md` F1 写清"已从主路径移除，原因：与 job 重复 + 定位漂移"，并把它的恢复条件限定为"确实需要逐账号干预"且以只读为主。
- **误砍风险**：`TOOL_PROTOCOL` 的兼容读入不能删——删了会让旧 `.env` 里的该变量触发未知配置告警或破坏向后兼容。只删"展示"和文档条目，不删 `config.js` 的读入。
- **口径漂移风险**：删除零引用类型字段时，若后端某日开始返回同名但非 null 的值，前端会静默丢弃。→ 护栏：在 `types.ts` 删除处留一行注释说明"后端若启用该字段需同步类型"，或保留为可选字段并标 deprecated。
- **回归风险**：本轮所有 UI 改动都必须跑 `npm test`、`npx tsc -b --force`、`npm run lint`，且**不得改任何后台 job / 调度 / 协议出口代码**。

### 7.3 执行顺序建议

1. **D2 + D3 + D4**（纯死代码/死配置，零行为风险）→ 一次提交完成。
2. **D1**（成长写按钮与轮询机）→ 独立提交，跑 `test:growth` 与 build。
3. **H1 + H2**（界面隐藏/合并）→ 独立提交，手工验收首登流程。
4. **O1 文案去游戏化** → 与 H1 一起做或随后单独做。
5. 所有 Prove-first 项先取证再定夺，**不要在本轮直接删后端端点**。

## 8. 一句话结论

> RelayGate 的核心功能都值得保留；真正该剃的是**重复入口、游戏化包装、死配置和零引用代码**。按第一批次执行后，产品定位会从"什么都有点的网关"收敛回"稳定、可信、能排障的账号池网关"，且不会破坏任何核心闭环或隐性必需复杂度。
