## 8. 整改优先级排序

### 8.1 分级依据

| 优先级 | 判据 | 时限建议 |
|--------|------|----------|
| **P0 立即** | 可被直接利用、或已发生实质数据暴露、或修复成本极低且阻断其他工作 | 24 小时内 |
| **P1 尽快** | 需特定权限但后果严重，或防护缺失使既有安全设计失效 | 1 周内 |
| **P2 计划** | 纵深防御、口径统一、稳定性 | 1 个迭代 |
| **P3 择机** | 可维护性与风格 | 随代码自然演进 |

### 8.2 P0 — 立即处理（2 项）

| 编号 | 问题 | 理由 | 具体动作 |
|------|------|------|----------|
| **H-04** | `logs/_wb-plain/` 明文 token | **已实际发生**：8 个账号的 accessToken/refreshToken 明文落盘超一个月。这不是理论风险 | ① 删除该目录<br>② **轮换全部涉及账号的 refreshToken**（视为已泄露）<br>③ 移除 `rotate-seed.js:120-130` 的明文读取分支 |
| **H-03** | 依赖已知漏洞 + `qs` 被 override 钉住 | 一条 `npm audit` 即可确认；override 会阻断正常升级路径 | ① 删 `overrides.qs`（或改 `^6.16.1`）<br>② 升 `body-parser >= 1.20.9`<br>③ 升 `express >= 4.22.3`<br>④ CI 加 `npm audit --audit-level=high` |

> **为什么 H-04 排在 H-01 之前**：H-01 需管理员凭据才能触发，H-04 的泄露**已经发生**。已泄露的凭据不会因为修好代码而失效。

### 8.3 P1 — 一周内（3 项）

| 编号 | 问题 | 理由 | 具体动作 |
|------|------|------|----------|
| **H-01** | `verifyBackup` 绕过路径闸门 | 任意文件读取 + 错误回显内容前缀。修复只需 3 行 | 在 `verifyBackup` 内首行调 `resolveBackupPath`，并去掉 `e.message` 回显 |
| **H-02** | Qoder 转发缺限流 | 烧穿真实积分；且注释已宣称有此防护——是"看似有实则无"的最坏形态 | `router.post('/chat/completions', authenticate, keyRateLimit(), ...)`（对照 `raccoon.js:545` 的正确写法）；补守门测试 |
| **M-04** | 明文密钥无遮蔽渲染 | 登录密钥明文上屏，肩窥/截图即泄露。前端改动局部 | `SecretBox` 默认掩码 + 限时显示 + 揭示确认 |

### 8.4 P2 — 一个迭代内（5 项）

| 编号 | 问题 | 具体动作 |
|------|------|----------|
| **M-01** | `normalizeKey` 静默补零/折叠 | 改为严格校验 64 位 hex，非法即抛带指引的错误 |
| **M-02** | sticky Map 无上限 | key 哈希归一并限长；加 `MAX_ENTRIES` 淘汰 |
| **M-03** | 解压炸弹 | `gunzipSync(buf, { maxOutputLength: 64MB })` |
| **M-05** | 管理面无失败限速/审计 | 按 IP 失败计数 + 退避；失败写 `audit()` |
| **M-07** | 错误回显面 | 管理面统一 `safeErrorMessage`；4xx 分支改为位置信息而非内容片段 |

### 8.5 P3 — 择机（低危与提示）

`L-01`~`L-08`、`N-01`~`N-07`。建议采取"顺手改"策略：下次改动相关文件时一并处理，不单独立项。

其中建议优先顺手处理的两项：

- **L-02**（日志脱敏按值特征兜底）—— 改动 5 行，收益是防止未来新增字段 fail-open。
- **L-08 / H-02 联动** —— 修 H-02 时同步修正 `qoder.js` 的注释，避免留下"注释说修了"的新漂移。

### 8.6 整改依赖关系

```
H-03（依赖升级）
  └─ 无依赖，可独立并行

H-04（明文凭据）
  └─ 必须先轮换 token，再改 rotate-seed.js
     （顺序反了会让轮换后的新 token 又被写进旧明文目录）

H-01（路径闸门）
  └─ 无依赖

H-02（限流）
  └─ 建议同时补守门测试，否则同类遗漏会复发

M-05（管理面限速）
  └─ 复用 H-02 引入的 keyRateLimit 结构，可合并为一次"限流装配审计"
```
