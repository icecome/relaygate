## 2. 根因修复说明（非表面补丁）

### M-S5 → platformResourceGate 统一关卡
- **表面修法（已否决）**：只在 trae/workbuddy 两个分支各插一段 canInvokeModel 调用——下次新增平台分支还会漏。
- **根因修法（已采用）**：抽 `platformResourceGate(authKey, model, meta)` 关卡，虚拟分支与 all 分支之外的「平台路由判定」路径一律经过；authKey 为 null 保持放行（内部调用语义不变）；workbuddy 分支透传 `{platform:'workbuddy'}` 保证资源路径映射正确。
- **防御性**：资源校验从「分支内可选 if」升级为「路径必经关卡」，新增平台分支默认被关卡覆盖。

### M-S6 → 环境变量单源
- **表面修法（已否决）**：加密后落盘——需要引入密钥管理与解密时序，复杂度与风险不成比例。
- **根因修法（已采用）**：密钥就不该进配置文件。normalizeProvider 强制剥离 apiKey（存量文件下次 save 自动净化），运行时仅经 `apiKeyEnv` 读 env。前端表单本就是 env 名输入，无需联动。

### M-P1 → 真流式
- **表面修法（已否决）**：聚合后用 setTimeout 分帧——仍是整段缓冲，只改善观感不改善 TTFB 与内存。
- **根因修法（已采用）**：复用项目既有流式设施（`llmUtilsChat(stream=true)` + `createLineFeeder` + `createStreamHandler`），逐事件直写 SSE；finish_reason 决策（tool_calls/截断优先）与 usage 三字段清洗同聚合出口等价。
- **测试防回归**：断言「首个内容帧写出早于上游流读取结束」——该断言在旧假流式实现下必然失败。

### m-32 → 单一事实源
- **表面修法（已否决）**：两开关都保留、文档说明「需同时开启」——语义碰撞仍在。
- **根因修法（已采用）**：删除 scheduler-settings 的 rotateEnabled 镜像；snapshot 兼容层把 `rotateEnabled` 指向真实开关，StatusPage 展示路径零改动。
